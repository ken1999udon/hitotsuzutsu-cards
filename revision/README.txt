第3章 Ethernet LAN 改訂版 — 作成基準と使い方

完成物
  dist/ネスペイージス_第3章_改訂版_170問.apkg
  dist/知識一覧とカード対応.csv
  dist/改訂版_全カード.csv
  dist/旧75問との対応.csv
  dist/知識一覧と作問記録.html

132項目の知識から、基本カード132枚と条件付きカード38枚を作成しました。
用語・数値だけでなく、転送ポートの判断、MACの更新、TTL、PoEの給電予算等を扱います。
14項目の問題数をそろえるための水増しはせず、追加する条件付きカードの目的を区別しました。

Ankiへの取り込み
  PC版Ankiの「ファイル」→「読み込む」から.apkgを選択します。
  デッキ名：ネスペイージス::第3章 Ethernet LAN 改訂版
  元の75問版とは別のデッキ・ノートタイプです。元の学習履歴は移行しません。
  元版を削除・変更する操作は行っていません。
  両方を並行して学習すると内容が重なるため、改訂版を使うときは旧版の扱いを選んでください。
  同じ改訂版の再取り込みでは識別子を維持し、カードの重複追加を避けます。
  再取り込み時の既存カード・学習履歴の保持は、Anki 26.9.4の一時プロファイルで確認しました。
  ノートのフィールド構成を変える更新は別途検討が必要です。

カードの構成
  表：カードIDと問題。分野名・解答・必須要素は出しません。
  裏：短い解答／正解に必要な要素／補足。
  裏の「前提・出典・対応する知識」を開くと、条件、参考URL、知識ID、過去問との接点を確認できます。
  言い換えても必須要素を満たせば正解です。補足を全文暗記する必要はありません。
  許容表現の例は、正解の表記をすべて列挙したものではありません。

タグ
  節::01〜14
  形式::知識／数値／動作／理由／計算／判断
  役割::基本カード／条件付きカード
  優先度::A／B／C

優先度の意味
  A：選んだ代表過去問で、その知識の直接出題または適用を確認した項目。
  B：理解や動作判断を支える基礎項目。作成者判断。
  C：規格名・数値・ピン番号・CLIなどの参照項目。作成者判断。
  Aは出題回数によるランキングではありません。B・Cが過去に出ていないことも意味しません。
  16の代表設問との接点を記録しましたが、全916小問の再監査や出題回数の集計はしていません。
  同じ小問に複数の知識が含まれるため、対応件数を出題回数として加算しないでください。
  過去問の参照は「直接／適用／前提／関連」を区別しています。

作成基準
  1. 元サイトの第3章14項目を確認し、事実・関係・条件を知識として独立させる。
  2. 各知識に出典と場所、条件、旧75問との対応、優先度の理由を付ける。
  3. 一枚のカードの主要な判断を絞り、正解の必須要素を問いに対応させる。
  4. 重要な動作に具体例を加え、各問題だけで解けるよう前提を繰り返す。
  5. 数値・単位・VLAN・受信ポート・転送状態・PSE/PD側等を明記する。
  6. 数値計算・具体的転送先を独立した計算でも確認する。
  7. 学習後の誤答は、知識の忘却と問題の不備を分けて記録し、改訂する。

知識の範囲
  採用した知識132項目すべてにカードがあります。
  これは元サイトの全文章・全図・全表の網羅や、試験の得点率を意味しません。
  歴史の年号、旧規格の表全体、製品型番・価格、現行法令確認を要するPLCの周波数、
  機種依存の既定値・しきい値など、今回は出題しない内容も節ごとに記録しています。
  詳細は data/review_policy.json と「知識一覧と作問記録.html」を参照してください。

出典の扱い
  元サイトは範囲の基準です。必要に応じてIEEE・Ciscoの一次資料で条件を確認しました。
  PDの正式名称、MACの一意性の条件、PSEとPDの電力差、フラッディングの範囲等を整理しています。
  元サイトの全文・図版は同梱していません。問題と解答は独自に作成しています。
  data/sources.json のハッシュは元サイトの取得時点の照合用です。再生成時の通信は不要です。
  LLDPの初期値や個別製品の能力等は、名称だけで全製品に一般化しません。

編集するデータ
  data/knowledge.json        覚える事実・関係・条件と、対応カードID
  data/cards.json            問題、短い解答、必須要素、補足、許容表現、具体例の検証用データ
  data/sources.json          出典のURL・見出し・確認日
  data/exam_evidence.json    選んだ代表過去問の参照情報
  data/review_policy.json    方針、優先度の定義、未カード化の範囲、確認の限界
  data/review_log.csv        学習結果・問題の不備を記録する空のテンプレート

データはGitで差分を確認しやすいJSON/CSVとして管理します。
Word版などの元ファイルは一階層上に残しています。

再生成と確認（revisionフォルダで実行）
  python -m pip install -r tools/requirements.txt
  python tools/build_deck.py
  python tools/verify_anki.py

生成スクリプトはデータを読み、APKG・CSV・HTMLを出力し、参照・知識対応・元75問の対応・
重複・必須要素の有無・15件の具体例計算・APKGデータベースを検証します。
verify_anki.pyはAnki本体のバックエンドを一時プロファイルで使い、全170枚の取り込みと
表裏の生成、再取り込みでの重複なし、既存カードの復習状態の保持を確認します。
実ユーザーのAnkiコレクションには触れません。AnkiのGUI操作自体の試験は未実施です。

改訂時はカードIDと知識IDを維持します。新しい知識・問いには新しいIDを割り当てます。
公開用更新時は data/review_policy.json のreviewed_on（Anki内の更新日にも使用）を進めます。
同日の複数リリースが必要なら、生成スクリプトのリリース時刻も明示的に変更してください。
dist内は生成結果なので、問題文の修正はdata内へ反映してから再生成します。

学習後の改訂
  review_log.csvに、カードID・自分の解答・自己判定・原因・コメントを記入します。
  issue_typeは次の4種類を目安にします。
    forgotten：内容を忘れた。復習を続ける。
    ambiguous：条件不足、別解、何を問うか不明。問題文や許容範囲を修正する。
    transfer：基本の答えは分かるが別条件で判断できない。具体例や説明を補う。
    content_error：解答・必須要素・出典との不一致。資料を確認して修正する。
  self_gradeには、correct / incorrect / ungradable を記録できます。
  問題の不備で判定できない場合は、忘却と混同せずungradableにします。
  実際の学習者の結果はまだありません。空の記録を架空の結果で埋めていません。

確認の限界
  資料照合と問題の条件点検は作成者が実施し、第三者専門家の査読は受けていません。
  機械検証は知識全体や自然言語の曖昧さを完全に保証するものではありません。

Git
  第3章フォルダがローカルリポジトリです。
  元75問のコミットと改訂版のコミットを分け、差分を記録しています。
  外部サービスへのpush・公開はしていません。
